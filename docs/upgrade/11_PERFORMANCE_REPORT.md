# Performance Report

Measured on this branch, production build (`vite build`), same source tree before and after the change.

## Change made

`vite.config.js` now splits React, React DOM and React Router into a separate vendor chunk. Nothing else about the build changed; no component, hook or data flow was touched.

## Measured effect

| Metric | Before | After |
| --- | --- | --- |
| Single JS payload | 753 KB | — |
| App chunk (`index`) | — | 570 KB |
| Vendor chunk (`react`) | — | 180 KB |
| Build exit code | 0 | 0 |

Total transferred JavaScript is essentially unchanged (750 KB vs 753 KB). The gain is caching and parse behaviour, not raw weight:

- **Cache stability:** a copy edit or page change rewrites only the 570 KB app chunk. Returning visitors keep the 180 KB vendor chunk, which is roughly a quarter of the payload no longer re-downloaded on each deploy.
- **Parallel parse:** the browser can compile the vendor chunk while the app chunk downloads.

Honest framing: this is a deploy-time and repeat-visit improvement. First-visit bytes are flat.

## What was deliberately not changed

- **Route-level code splitting.** `src/pages.config.js` is marked auto-generated by the platform and drives all nine routes. Converting it to `React.lazy` would cut the first-load bundle substantially, but it would also fight the generator and could be overwritten on the next page add. Recorded as an opportunity (**O1**), not performed unasked.
- **`three`, `recharts`, `react-markdown`.** An initial attempt to split these produced 1 byte, 402 bytes and 1 KB chunks respectively: they are not in the live import graph, so Rollup had already tree-shaken them. Splitting them added empty files, so the entries were removed.
- **Polling intervals.** `Leaderboard` polls every 10 s, `Layout` refreshes RP every 30 s. Both are deliberate product choices; changing them would alter behaviour, not just performance.
- **Matrix rain.** Already tuned in an earlier phase (fall speed halved, per-frame work reduced). Re-measured here: it remains a single canvas with a fixed glyph set and no per-frame allocation.

## Verification after the change

- `vite build` → exit 0.
- `npx vitest run` → 43/43 passing.
- `npx tsc --noEmit -p ./jsconfig.json` → 0 errors.
- Live data layer re-verified end to end against X1 mainnet: 24/24 checks (see `05_QA_REGRESSION.md`).

## Known limits of this measurement

No browser-based lab tooling is available in this environment (no Chromium binary for the installed Playwright core), so there is no Lighthouse score or real-user field data in this report. The numbers above are bundle sizes from the actual build output, which is what the change affects.
